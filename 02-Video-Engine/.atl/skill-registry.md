## Compact Rules

### project-video-pipeline (local convention)

- Input naming convention in `audio/`:
  - `audio-16khz.wav` → STT/transcription backend input.
  - `audio-48khz.wav` → final render audio (preferred).
- Render fallback order:
  1. `audio/audio-48khz.wav`
  2. `audio/audio-16khz.wav`
- Timeline integrity:
  - First segment must start at `0.00` to avoid initial black frames.
  - No gaps/overlaps between segments (`endTime` of current = `startTime` of next after fix step).
  - Last segment must end at full render-audio duration (not only last spoken word).
- STT backend selection:
  - Prefer `whisper` (`faster-whisper`) in `auto` mode.
  - Keep Vosk/DeepSpeech-compatible fallback available.

### remotion-best-practices

- For Remotion code, prioritize timeline-accurate sequencing (`Sequence`, `Audio`, `calculateMetadata`) and deterministic frame math.
- Use dedicated rule docs for domain-specific work: captions/subtitles, FFmpeg operations, audio visualization, transitions, composition metadata.
- Keep media handling explicit (asset paths, duration calculations, composition props).

### branch-pr

- Every PR must link an approved issue.
- Use exactly one `type:*` label in PRs.
- Follow conventional commits and valid branch naming (`type/description`).
- Ensure automated checks pass before merge.

### issue-creation

- Use issue templates (no blank issues).
- New issues start as `status:needs-review`; PRs require `status:approved`.
- Prefer Discussions for questions; Issues for actionable work.

### go-testing

- Prefer table-driven tests for multiple scenarios.
- Validate behavior with deterministic assertions.
- For Bubbletea, test model state transitions directly.

### judgment-day

- Use two independent blind judges in parallel.
- Synthesize findings into confirmed/suspect/contradiction buckets.
- If fixes are needed, re-judge up to 2 rounds before escalation.

### skill-creator

- Create skills only for recurring, non-trivial patterns.
- Use standard skill structure (`SKILL.md`, optional `assets/`, `references/`).
- Include clear triggers, critical patterns, and minimal focused examples.
